# DocVault

Локальный архив PDF, JPG, JPEG и PNG с прежним интерфейсом Windows Forms: добавление файлов, поиск по названию и тегам, просмотр, изменение описания и удаление. Данные остаются на компьютере пользователя.

## Что делает Docker

Docker **собирает Windows-приложение**, а не запускает его графический интерфейс. Linux-контейнер SDK выполняет кросс-компиляцию для `win-x64`. Полученный EXE запускается в Windows, содержит среду .NET и не требует отдельной установки .NET Runtime.

Прежний консольный режим, который только создавал БД и печатал heartbeat, удалён: он не предоставлял функции архива. Для сохранения прежнего окна Windows Forms выбран контейнер сборки, а не новый веб-интерфейс.

## Сборка через Docker Compose

Требуется работающий Docker Engine с Linux-контейнерами и Docker Compose v2. На Windows подходит Docker Desktop. Из каталога проекта выполните:

```powershell
docker compose run --build --rm build-windows
```

После завершения найдите `artifacts/DocVaultLocal.exe`. Скопируйте EXE в отдельную доступную для записи папку Windows и запустите. Контейнер завершится после выгрузки сборки — это ожидаемое поведение. Проброс портов, сервис БД и постоянные Docker-тома не нужны.

Альтернатива с BuildKit, без запуска контейнера экспорта:

```powershell
docker build --target artifacts --output type=local,dest=./artifacts .
```

Первоначальная сборка требует интернета для загрузки SDK и пакетов NuGet. Работа готового приложения не требует сети. PDF открывается установленной в Windows программой просмотра.

## Воспроизводимость

Версия SDK `9.0.317` зафиксирована в `global.json`, образ SDK — по digest в Dockerfile, зависимости — в `packages.lock.json`. Сборка контейнера использует `dotnet restore --locked-mode`. Это фиксирует входные версии; побайтовая идентичность EXE отдельно не проверялась.

## Где находятся данные

База `docvault.db` создаётся рядом с EXE. Копии файлов находятся в папке `Storage` рядом с ним. Запуск через ярлык или из другой текущей папки не переключает базу. Не храните рабочий архив в каталоге результатов сборки `artifacts`.

Если старая версия создавала БД в другой рабочей папке, закройте приложение и сохраните резервную копию перед переносом. Перенесите нужную БД рядом с EXE. В базе могут быть абсолютные пути к архивным файлам: оставьте прежнюю папку Storage по прежнему пути или отдельно обновите пути. Автоматическая миграция чужого каталога не выполняется.

Резервная копия включает БД и всю папку Storage при закрытом приложении. Локальное хранение не является шифрованием. При добавлении исходный файл не меняется, при удалении удаляется его архивная копия.

## Проверка без Docker

При установленном .NET SDK 9.0.317:

```powershell
dotnet restore DocVaultLocal.csproj -r win-x64 --locked-mode
dotnet publish DocVaultLocal.csproj -c Release -r win-x64 --self-contained true --no-restore -p:PublishSingleFile=true -o artifacts
dotnet run --project tests/ArchiveSmokeTests.csproj -c Release
```

Тесты создают отдельную временную БД в каталоге тестовой сборки и отказываются работать, если там уже есть БД. Они проверяют путь к базе, операции каталога, параметризацию поиска и сохранение записей при повторной инициализации.

## Проверенный результат

На 20.09.2026 успешно выполнены публикация Windows EXE, запуск его прежнего интерфейса с инициализацией каталога, проверки операций БД и `docker compose config --quiet`. Существующие nullable-предупреждения не препятствуют сборке.

Полная сборка внутри Linux-контейнера в доступной среде не запускалась: Docker Desktop возвращал `Docker Desktop is unable to start`. Локальная публикация не заменяет эту проверку. После восстановления Docker нужно выполнить команду Compose выше и проверить полученный EXE на Windows.
